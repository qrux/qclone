qclone v1, as built

2026-10-13 · repo ~/proj/qrux/qclone (github.com/qrux/qclone) · released as 0.1.0 · written by the Claude Code session that built it

There is no spec for this revision. qclone was built from Q's request in chat on 2026-10-12, so this document records the decisions as they were made in that conversation rather than against a written spec. A spec for revision 2 should start from here.

1. What was asked

  • An rclone-like copier (first named tclone) that tries hard never to show a transfer rate of 0 B/s, unless there are errors.
  • It works out by itself, using iostat or similar, whether more parallel copies are faster, and adjusts while running. The case to handle: a degraded SSD whose old, never-rewritten regions read at about 2 MB/s while fresh regions read at 500 MB/s.
  • Errors go to a file, by default <timestamp>-tclone-errors.txt, never to stderr. Redrawing the whole window is fine.
  • Several source directories. /path/to/source copies the directory itself; /path/to/source/ copies its contents.
  • A display as nice as possible, with ASCII-art progress bars.
  • Later in the session: a rescue mode (interrupted copies resume, unreadable spots are mapped), the rename to qclone, an Apache-2.0 license, publishing under the qrux GitHub account, and a Homebrew tap.

2. What was built

A single Go binary, qclone, macOS first: qclone [flags] SRC [SRC...] DST.

3. Choices made, and why

3.1 Scope and conventions

  • Go, standard library only (no third-party modules), with cgo for IOKit and clonefile.
  • Local to local only. No cloud remotes, which is why the Homebrew description says "local rclone".
  • Source rule as asked, plus the rsync details: src/. and . also mean contents; a file lands under its own name; a symlink source is copied as a link unless it has a trailing slash.
  • Like rclone copy: files at the destination with the same size and modification time (within 1 s) are skipped, so a rerun picks up where it stopped. Modes, modification times, symlinks and empty directories are copied. Directories get their modes at the end, so a read-only source folder doesn't stop a rerun from writing.
  • Overlap checks compare files by identity, not by name: a destination inside a source, a contents source inside its destination, a file onto itself. Name checks were fooled by APFS ignoring letter case. Duplicate destination files across sources are compared with case folded when the destination ignores case.
  • Atomic installs. Each file is written to a hidden .qclone-<hash>.part beside its destination, fsynced, then renamed, so a crash never leaves a complete-looking file that is really partial.
  • No OS file cache by default (F_NOCACHE, --cached to turn it off). The rate shown is then the disk's, and the reads in flight are exactly the tuner's setting, with no read-ahead added.
  • Errors: <timestamp>-qclone-errors.txt in the current folder (--errors FILE to move it), created only when the first error happens. Only bad arguments go to stderr. Exit status: 0 done, 1 some errors, 2 bad arguments, 130 stopped.
  • Paths never reach stdout. The display goes to the terminal, or to /dev/tty when stdout is a pipe; stdout then gets path-free status lines every 10 s. That keeps runlog logs free of file names.

3.2 The rate never reads zero

  • The rate is measured from a baseline: the window covers at least 4 s, and stretches back further until it holds 4 completed reads. While a read is stuck the window keeps growing, so the rate decays toward the true average instead of dropping to zero. After 5 s with nothing landing, the display adds "no read finished for Ns".
  • The per-disk rates work the same way, reaching back up to 2 minutes. A disk with no activity at all shows "idle for Ns", never "0 B/s".
  • Before the first byte the display says "starting", and a file still waiting on its first read says "wait Ns".
  • The peak shown is never below the average, which fixed a 0 B/s peak in runs shorter than the 100 ms sample.

3.3 The tuner

  • Two dimensions: readers in flight, and chunk size. Defaults: start at 4 readers (rclone's default) and 256 KiB chunks; readers range from 1 to 32 (--max-readers up to 256), since 32 is the SATA queue-depth limit; chunks range from 128 KiB to 8 MiB.
  • Rounds of five arms, A C A C A (A the current setting, C a candidate). Each C is scored against the mean of the A arms on either side, which cancels steady drift in the drive's speed.
  • Fluid measurement: each finished read+write is spread over its own start-to-end interval, so arm boundaries are exact even when one read takes seconds.
  • Two-generation settle. Measuring starts only after the reads begun under the old setting, and those begun while they were running, have finished. With one generation, a deeper queue measured 15–20% better than it was. Found and fixed in simulation.
  • Thresholds: more readers must gain 5%; fewer readers may cost up to 2%. A bigger chunk must gain 3%; a smaller one may cost up to 2%. The chunk grows only while reads take under 0.5 s.
  • Speed-ups: readers double per step at the start and after entering a slower region, until a step stops paying. A round ends early after A C A when the difference passes 25%.
  • Rounds thrown out: when the A arms disagree by more than 2.5× (a region change); when a result claims more than the change could cause (twice the readers can at most double throughput); when the disk read much more than qclone did (something else was using it, per IOKit).
  • Region memory: the best setting is kept per speed level, and the tuner jumps back to it when it re-enters a region of that speed.
  • Tuning pauses when less than about 10 s of work is left, or the scan can't keep up.

3.4 Display

  • Full screen on the alternate screen; the last frame stays in scrollback at the end. Redrawn 4 times a second in a single write, using a synchronized update.
  • ASCII only for the drawing. Bars look like [#####>....]. The speed chart is log-scale with round-number rows (a 1-2-5 ladder) and colored by slowness, with the reader count charted beneath it. File names are shown as they are, with control characters replaced.
  • Sections: total, speed chart, the tuner's live arms and last verdict, the source and destination disks (model, interface, rates, time per read, queue depth, the disk's own error counters), per-file bars, errors.
  • Sizes and rates in decimal units (kB, MB, GB), as Finder uses. Works from 20 columns up, without panics.

3.5 Rescue

  • Resume: a .qclone-<hash>.map beside each part records the byte ranges written. It's saved every 2 s after an fsync, and when a run stops. A rerun with the same source size and time copies only what's missing.
  • Unreadable spots are bisected down to 4 KiB after 3 tries, with at most 64 failed reads per chunk.
  • Without --rescue, such a file isn't installed; its part and map are kept, and a rerun retries just the spots.
  • With --rescue, the spots are zero-filled, the file is installed, and a .bad marker is written first. Later runs clone the installed file (instant on APFS) and re-read only those spots.
  • Every spot is listed by byte offset in the error file. The display and summary show counts only.

3.6 Naming, ownership, license, publishing

  • Renamed tclone to qclone. Of the names checked, it had the fewest collisions: only an unrelated npm package. "qlone" is a commercial 3D-scanner app.
  • Author identity: the repo's own git identity is Qrux <797788+qrux@users.noreply.github.com>. Every commit was rewritten to it, and no history with Q's legal name remains.
  • License: Apache-2.0, Copyright © 2026 Qrux. NOTICE says "qclone was created by Qrux", and section 4(d) makes every distribution carry it. Chosen after make license-probe: among Homebrew's Go tools, 42.8% are MIT and 38.0% Apache-2.0.
  • Pushes go through the github-qrux SSH alias, so they authenticate as qrux.
  • Builds use -trimpath -ldflags "-s -w", so binaries carry no local paths.
  • Homebrew: a formula in the tap qrux/homebrew-tap, built from the tagged source on the user's Mac, so no signing or notarization is needed. Description: "Prettier local rclone: cleaner syntax, adaptive parallelism, degraded-SSD rescue".

4. Where the build departs from the request

  • "iostat or whatever": the counters come straight from IOKit's IOBlockStorageDriver statistics, the same numbers iostat reads, without starting a process ten times a second.
  • "Always something positive": before any data has moved there is nothing to measure, so the display says "starting". A disk that has done nothing at all says "idle".
  • Errors and stderr: bad arguments still go to stderr, since there's no run yet and nowhere else to say it.

5. What was verified, and how

  • make test: go vet, then every test with the race detector, all passing. Q's logged run passed after the rename. The tests cover:
    • the rate meter through a ten-minute stall;
    • the tuner in virtual time on scalable, non-scalable, fast, alternating, overhead-bound and noisy drives;
    • argument rules and refusals;
    • byte-exact tree copies with modes, times and links;
    • errors only in the error file, with nothing on stderr;
    • cancel, resume (no byte read twice) and rescue (exact spots, zero-fill, re-read after recovery);
    • map truthfulness mid-copy;
    • frames at every width from 20 to 79 columns.
  • Demos on the simulated degraded drive: 972 MB, 362 files. Tuned: 52 s at an average of 18.8 MB/s. Fixed at 4 readers × 1 MiB (rclone's shape): 2:31 at 6.46 MB/s. Copies byte-identical (diff -r). The 2.9× depends on the simulator's assumption that slow regions speed up with more reads in flight.
  • Rescue demo on --simulate failing: 21 spots, 86 kB, in 9 files. The plain pass kept the parts; the --rescue pass read only the spots and installed the files with zeros; a pass on the recovered drive read 86 kB and ended byte-identical.
  • A code review by a separate agent found 13 defects, all fixed with regression tests. Among them: a panic on narrow terminals; the case-blind copy-into-itself recursion; case-colliding temp files; read-only folders blocking retries; stale chunk sizes in tuner tests; mixing wall-clock and monotonic time.
  • Release 0.1.0: tag v0.1.0 on 0f0321b, tagged by Qrux. The tarball's SHA-256 is 676fc78024cd3e550514fae6d36c054d2d5710905d5425763f69d535279a07d2, the same on repeated downloads; built from it, the binary reports qclone 0.1.0.
  • Homebrew: make brew-check tapped qrux/tap, passed brew audit --strict --online, built from source, and passed the formula's test. qclone on the PATH is Homebrew's 0.1.0.

6. Releasing a new version

  1. Commit the changes and push them: 
    git -C ~/proj/qrux/qclone push
  2. Release, with the new version number: 
    make -C ~/proj/qrux/qclone release VERSION=0.2.0
    It refuses to run if main has uncommitted changes or differs from GitHub's. Otherwise it:
    • runs go vet and the tests;
    • tags v0.2.0 and pushes the tag;
    • downloads GitHub's tarball for the tag and builds it the way the formula does (qclone --version must print qclone 0.2.0);
    • writes Formula/qclone.rb with the tarball's checksum into the tap, commits as Qrux, and pushes.
    DRY_RUN=1 does everything except the pushes. Run against a tag that's already on GitHub, it republishes that tag's formula.
  3. Optionally, check the result the way a user gets it. This installs qclone from the tap through Homebrew: 
    make -C ~/proj/qrux/qclone brew-check

Users get the new version with brew upgrade. To change the formula itself (its description, dependencies or test), edit packaging/homebrew/qclone.rb.in in qclone, not the tap. The next release writes it.

7. Still open

  • Never yet run on the real degraded drive. Whether its slow regions speed up with more reads in flight is up to its controller. A USB bridge without command queuing limits it to one read at a time, and the disk panel's queue figure will show that.
  • Not copied: extended attributes, ACLs, resource forks, Finder tags, file flags, ownership, hard links (each becomes its own file), symlink times.
  • No cloud remotes.
  • Copyright in AI-written code is uncertain in the US. Q directed the work and Claude wrote most of the code. Worth a lawyer's view before relying on the copyright, for example in a sale.
  • Published 2026-10-13, public from the first push. The US one-year window for patenting anything in it runs from then; outside the US it's already closed.
  • Prebuilt binaries, if ever distributed, should carry Go's BSD notice. The tap builds from source, so it doesn't need it.
  • Every commit message carries a Claude co-author line, so GitHub shows Claude as a co-author.
  • homebrew-core (a plain brew install qclone) needs notability: about 30 forks, 30 watchers or 75 stars.
  • runlog flags Go package names such as qclone/internal/ui as paths, so every test log ends with a WARNING footer.
  • The tuner's chunk-size measurement showed a residual bias of about 4% toward bigger chunks in the simulator, where queues fill slowly. Growth is limited to reads under 0.5 s; real drives may differ.
